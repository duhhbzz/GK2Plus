# GK2+ Configuration

GK2+ supports two configuration paths:

1. **Recommended for most players:** use the GK2+ menu in-game.
2. **Advanced/manual configuration:** edit the BepInEx configuration file directly or through a compatible mod manager such as r2modman/Thunderstore Mod Manager.

Both paths edit the same underlying settings. The in-game UI is not intended to maintain a separate settings database.

## Config file

GK2+ uses BepInEx configuration entries. After the game has launched with GK2+ at least once, BepInEx creates:

~~~text
BepInEx/config/com.duhhbzz.gk2plus.cfg
~~~

A mod-manager profile keeps its own copy under that profile's BepInEx/config directory.

## Recommended workflow

For normal use, configure GK2+ from its own menu. The in-game menu can apply GK2+-specific safety rules such as limiting certain changes to the main menu and showing the current runtime status.

Advanced users are free to edit the `.cfg` file directly or use a mod manager's configuration editor.

Changes made outside the game should be treated as **next-launch settings** unless a specific feature explicitly documents live reload support.

## Setting descriptions

Every player-facing setting should use a BepInEx `ConfigEntry` with:

- a stable section/key;
- a sensible default;
- a useful description;
- an acceptable range/list when practical.

Those descriptions are intentionally useful outside GK2+ as well. Config editors can surface the setting name, value type, default/current value, and description.

## Source of truth

The BepInEx `ConfigEntry` is the source of truth.

Feature UI controls should read from and write to that same config entry rather than keeping a second independent copy of the setting.

This prevents these from drifting apart:

~~~text
GK2+ menu
r2modman / Thunderstore config editor
manual .cfg editing
runtime feature behavior
~~~

## Feature enable/disable settings

Major gameplay features should expose a normal BepInEx boolean setting when technically practical.

Example shape:

~~~ini
[Inventory]

## Access other eligible storage in the current world zone from a normal chest window.
# Setting type: Boolean
# Default value: true
shared-chests.Enabled = true
~~~

The exact comments/format are generated by BepInEx and may vary by runtime/tooling.

## Parent and child settings

If a setting only matters when its parent feature is enabled, the GK2+ menu should keep it visually grouped beneath that feature.

Example:

~~~text
Bigger Item Stacks                         [ ON ]
    Stack Size Multiplier                  [ 3x ]

Shared Chests                              [ ON ]
~~~

When the parent feature is OFF, its child settings should remain visible so the saved value is understandable, but they should be visually disabled/non-interactive until the feature is enabled again.

The config value itself remains valid and should be preserved. Turning a feature off should not erase its configured child values.

## For contributors

When adding a player-facing setting:

- bind it through BepInEx configuration;
- use that config entry as the runtime/UI source of truth;
- give it a clear description for config-editor users;
- declare its menu order/group relationship;
- declare its parent feature when it is a child setting;
- document whether changing it is main-menu-only, live-safe, or restart-required;
- document it in [FEATURES.md](FEATURES.md).

Do not add an in-game-only setting that cannot also be represented in GK2+'s normal configuration system unless there is a technical reason documented in the PR.
